# 區域製作手冊

這份手冊說明 `areas/` 裡區域檔的寫法，以及每個欄位的意思。範例以 `areas/test.json` 為準。

每個欄位都標了新系統（這個 Python 伺服器）實作了沒：
- ✅ 已實作：伺服器已經在用。
- 🔍 只檢查格式：載入時會檢查寫得對不對，但遊戲裡還沒有效果。
- ⏳ 還沒做：伺服器載入時不會讀它。
- 🔒 保留：先留著，之後再設計。

## 基本規則

- 區域檔放在 `areas/` 資料夾，副檔名是 `.json`，用 UTF-8 存檔。
- 伺服器開機時會載入 `areas/` 裡全部的區域檔。
- 區域檔有錯時，伺服器會說明是哪個檔案、哪一間房間錯了，然後停止開機。會報錯的情況有：
  - 格式不對
  - 少了欄位，或多了這份手冊沒有的欄位
  - 號碼重複
  - 出口通到不存在的房間
- 文字裡要換行就寫 `\n`。描述的最後最好也加 `\n`；沒加的話，伺服器會自己補上。
- 房間名稱、房間描述、出口描述、可細看的東西的描述，都可以用[顏色代碼](#顏色代碼)。

## 號碼規則

- 每個區域檔有一個 `area_number`，寫在 `area.header` 裡。
- 檔案裡的房間、物品、生物號碼，各自只能是 **1～99**，所以一個區域最多 99 間房、99 種物品、99 種生物。
  三種號碼分開算：房間 101 和生物 101 可以同時存在。
- **遊戲裡的號碼 ＝ `area_number` ＋ 檔案裡的號碼**。例如 `area_number` 是 3200，物品 3 在遊戲裡就是 3203。
- 遊戲號碼 1～99 是保留的，不能使用，所以 `area_number` 不能是 0。算出來小於 100 就會報錯。
- `area_number` 不一定要是 100 的倍數，但算出來的遊戲號碼不能跟別的區域重複。
- 要指到某個房間、物品或生物時，例如出口的 `to_room`、門的鑰匙 `key`、回城的 `recall`、生物的掉寶 `random_drop.obj_vnum`、
  重置的 `room_vnum`、`mob_vnum`、`obj_vnum`、`container_vnum`，都有兩種寫法：
  - 寫 **1～99**：代表同一個區域裡的房間或物品，伺服器會自動加上 `area_number`。
  - 寫 **100 以上**：代表完整的遊戲號碼，用來指到別的區域。

  例如 `test.json` 的 `area_number` 是 100，房間 1 北邊的出口寫 `"to_room": 2`，實際上就是通到 102 號房間。
  `key` 另外還可以寫 `-1` 或 `0`，代表不用鑰匙。

### room_flags（房間旗標）

可以寫數字，也可以寫字串：
- 數字：`0`、`5`
- 字串：`"0"`、`"5"`、`"1|4"`

`|` 的意思是把幾個旗標合在一起。例如 `"1|4"` 代表「很暗」加上「怪物不會走進來」，等於 `5`。合起來不是相加：`"1|3"` 是 3，不是 4。不需要任何旗標時寫 `0`。

| 數字 | C 版名稱 | 意思 |
|---|---|---|
| 1 | dark | 很暗 |
| 4 | no_mob | 怪物不會走進來 |
| 8 | indoors | 室內 |
| 16 | underground | 地底：吸血鬼白天在這裡不怕陽光 |
| 32 | clanrest_lv1 | 幫派休息室（第 1 級） |
| 64 | clanrest_lv2 | 幫派休息室（第 2 級） |
| 128 | clanrest_lv3 | 幫派休息室（第 3 級） |
| 256 | clanroom | 幫派房間：只有這個幫派的人能進來 |
| 512 | private | 私人房間：最多 2 個人 |
| 1024 | safe | 安全區：不能戰鬥 |
| 2048 | solitary | 單人房：最多 1 個人 |
| 4096 | pet_shop | 寵物店 |
| 8192 | no_recall | 不能用回城 |
| 16384 | cone_of_silence | 不能說話（頻道和 tell 都不能用） |
| 32768 | no_murder | 不能殺玩家 |
| 65536 | fen | 沼氣：不會飛的人會中毒 |
| 131072 | no_summon | 不能用召喚術（C 版註解：不可 cast summon 的房間） |
| 262144 | half_gain | 回復力減半 |
| 524288 | no_teleport | 傳送術不會落在這間房 |
| 1048576 | deadtraps | 死亡陷阱：走進來就會死（神族除外） |
| 2097152 | bank | 銀行 |
| 4194304 | damagetrap | 每個 tick 扣一半的生命、法力和體力 |
| 8388608 | eqbank | 裝備銀行 |

### sector（地形）

只能寫 0～10 的一個整數，因為一間房只會有一種地形。

| 數字 | C 版名稱 | 意思 |
|---|---|---|
| 0 | inside | 室內 |
| 1 | city | 城市 |
| 2 | field | 原野 |
| 3 | forest | 森林 |
| 4 | hills | 丘陵 |
| 5 | mountain | 山地 |
| 6 | water_swim | 可以游泳過去的水 |
| 7 | water_noswim | 要有船才能過去的水 |
| 8 | underwater | 水底，要會在水裡呼吸 |
| 9 | air | 空中，要會飛 |
| 10 | desert | 沙漠 |

### exits（出口）

`exits` 的 key 是方向，只能用這六個：`north`、`east`、`south`、`west`、`up`、`down`。每個方向寫一個出口：

| 欄位 | 意思 | 新系統 |
|---|---|---|
| `description` | 往這個方向看到的樣子。玩家打 `look n`、`look north` 時顯示這段文字，不是隔壁房間的描述。可以寫空字串 `""`，這時會顯示「那裡沒有什麼特別的東西。」 | ✅ 已實作 |
| `keywords` | 門的名字，多個名字用空白隔開，例如 `"鐵門 gate"`。只有有門的出口才用得到，沒有門就寫 `""` | ⏳ 還沒做 |
| `locks` | 門的種類，見下表 | ⏳ 還沒做 |
| `key` | 開這扇門要用的鑰匙（物品號碼）。寫法同 `to_room`：1～99 是這個區域的物品，100 以上是別的區域的完整號碼。寫 `-1` 或 `0` 代表不用鑰匙 | ⏳ 還沒做 |
| `to_room` | 通到哪一間房，寫法見[號碼規則](#號碼規則) | ✅ 已實作 |

`locks` 的值：

| locks | 意思 |
|---|---|
| 0 | 沒有門 |
| 1 | 門 |
| 2 | 門，撬不開 |
| 3 | 門，撞不開 |
| 4 | 門，撬不開也撞不開 |
| 5 | 門，法術穿不過去 |
| 6 | 門，撬不開、法術穿不過去 |
| 7 | 門，撞不開、法術穿不過去 |
| 8 | 門，撬不開、撞不開、法術穿不過去 |

- 撬：pick 指令；撞：bash 指令；法術穿過去：穿門術（pass door）。
- 門一開始是開著、關著還是上鎖，不在這裡設定，以後由重生設定決定。

門的功能還沒做，但訊息規則已經定好：門關著還要走過去時，有寫 `keywords` 就顯示「【鐵門】關起來了。」（用第一個名字）；沒寫 `keywords` 就用方向，例如「北方關起來了。」

### extra_descriptions（可以細看的東西）

一個清單，每一項是一樣可以細看的東西：

| 欄位 | 意思 | 新系統 |
|---|---|---|
| `keywords` | 名字，多個名字用空白隔開，例如 `"牌子 sign"`。不能是空的 | ✅ 已實作 |
| `description` | 細看時顯示的文字 | ✅ 已實作 |

- 玩家打 `look 牌子` 或 `look sign` 就會看到 `description`。
- 名字要打完整：打 `look 牌` 找不到「牌子」。英文不分大小寫，`look SIGN` 也可以。
- `look` 會先找東西，再找方向。所以如果有東西取名叫 `north`，`look north` 會看到那樣東西，而不是北邊的出口。取名時要避開方向的英文。
- 沒有東西可以細看時，寫空清單 `[]`。

### script（保留）

房間的觸發程式，例如有人在房間裡說話時執行一段程式。目前格式是：

```json
"script": {
  "trigger": {"value": 64, "names": ["say"]},
  "function": "rs_test_say"
}
```

沒有觸發程式時寫 `null`。`script` 和裡面的 `function` 先保留，等之後設計腳本系統時再決定怎麼寫。

## mobiles（生物）

生物就是怪物、商人、守衛這些不是玩家的角色。欄位是照舊版區域檔整理出來的，之後會刪掉用不到的。

- 遊戲還不會讓生物出現。生物要放在哪個房間，寫在[重置](#resets重置)的 `M`。
- 現在只檢查寫法：欄位要剛好、數字要是整數（`exp` 可以有小數）、文字要是字串。數字代表什麼（例如旗標有沒有這一格）還沒檢查。
- 「C 版讀了就丟」是說 C 版的程式讀了這個欄位以後，連存都沒存。
- 舊版的 `hitroll`、`ac`、`hit_dice`、`damage_dice`、`gold`、`custom`（K 行）已經拿掉了，新系統也不會用。寫了會被當成不認得的欄位。

| 欄位 | 意思 | 新系統 |
|---|---|---|
| `vnum` | 檔案裡的生物號碼，只能是 1～99，見[號碼規則](#號碼規則) | 🔍 只檢查格式 |
| `keywords` | 玩家用來指定牠的名字，多個名字用空白隔開，例如 `"merchant 商人"`。不能是空的 | 🔍 只檢查格式 |
| `short` | 短名稱，例如 `"測試商人"`。不能是空的 | 🔍 只檢查格式 |
| `long` | 在房間裡看到牠時顯示的那一行。舊區域的寫法是「一位測試商人/merchant/站在櫃檯後面。」 | 🔍 只檢查格式 |
| `description` | 用 `look` 看牠時顯示的描述 | 🔍 只檢查格式 |
| `level` | 等級。C 版載入時會隨機加減 1 | 🔍 只檢查格式 |
| `act` | 行為旗標，寫法同 `room_flags`（數字或 `"2\|64"`），見[act](#act行為旗標) | 🔍 只檢查格式 |
| `affected_by` | 身上帶著的效果，寫法同 `room_flags`，見[affected_by](#affected_by身上的效果) | 🔍 只檢查格式 |
| `alignment` | 陣營，-1000（邪惡）～1000（善良） | 🔍 只檢查格式 |
| `race` | 種族名稱，例如 `"human"`，見[race](#race種族)。C 版比對名稱的開頭，不分大小寫 | 🔍 只檢查格式 |
| `sex` | 性別：0 中性、1 男、2 女 | 🔍 只檢查格式 |
| `exp` | 經驗值的倍數，平常寫 `1`。寫 `0` 不給經驗值，`1.5` 多給 50%。實際給多少經驗值，之後由等級和稀有度算出來（稀有度是[重置](#resets重置) `M` 的 `rare`），再乘上這個倍數 | 🔍 只檢查格式 |
| `position` | 姿勢，見[position](#position姿勢)。C 版讀了就丟 | 🔍 只檢查格式 |
| `random_drop` | 死掉時隨機掉出的物品，見[random_drop](#random_drop隨機掉寶)。不用時寫 `null` | 🔍 只檢查格式 |
| `script` | 生物的觸發程式，寫法跟房間的 [script](#script保留) 一樣，觸發條件見[trigger](#trigger觸發條件)。沒有時寫 `null` | 🔍 只檢查格式 |
| `actions` | 平常的動作，見[actions](#actions平常的動作)。沒有時寫 `[]` | 🔍 只檢查格式 |
| `fight_actions` | 戰鬥中的動作，見[fight_actions](#fight_actions戰鬥中的動作)。沒有時寫 `[]` | 🔍 只檢查格式 |
| `shop` | 牠開的商店，見[shop](#shop商店)。不是店主就寫 `null` | 🔍 只檢查格式 |
| `special` | 寫在程式裡的行為，挑一個名稱，見[special](#special特殊程式)。沒有時寫 `null` | 🔍 只檢查格式 |

### random_drop（隨機掉寶）

舊版的 R 行：生物死掉時，有機會掉出一件物品。

| 欄位 | 意思 |
|---|---|
| `chance` | 機率，以萬分之一為單位：`5000` 是 50% |
| `obj_vnum` | 掉出的物品號碼，寫法見[號碼規則](#號碼規則)。這個物品存不存在，目前還不會檢查 |

### actions（平常的動作）

舊版的 A 行。同一個時機有好幾筆時，隨機挑一筆。C 版裡，生物要站著、沒被魅惑才會做。

| 欄位 | 意思 |
|---|---|
| `when` | 什麼時候：`0` 每個 tick（不在戰鬥中時）、`1` 有人走進房間時 |
| `mode` | 怎麼做：`0` 當成指令執行（例如 `"say 歡迎光臨！"`）、`1` 對整個房間顯示這段文字、`2` 對走進來的人顯示這段文字 |
| `text` | 指令或文字，可以是空的 |

### fight_actions（戰鬥中的動作）

舊版的 F 行。戰鬥中隨機挑一筆，照機率發動。

| 欄位 | 意思 |
|---|---|
| `rate` | 發動的機率（%）。寫負數時，對象改成自己或主人 |
| `message` | 發動時顯示的文字，`%s` 會換成對象的名字 |
| `command` | 要執行的指令，`%s` 會換成對象，例如 `"cast 'inflict pain' %s"` |

| `profit_buy` | 玩家向牠買東西時的價格倍率（%） |

## objects（物品）

物品就是裝備、藥水、鑰匙、容器這些東西。欄位是照舊版的 `#OBJECTS` 整理出來的，之後會刪掉用不到的。

- 遊戲還不會讓物品出現。物品要放在哪裡，寫在[重置](#resets重置)的 `O`、`P`、`G`。
- 現在只檢查寫法：欄位要剛好、數字要是整數、文字要是字串、`values` 要剛好 4 個。數字代表什麼（例如種類有沒有這一種）還沒檢查。
- 物品沒有等級欄位：C 版的物品等級是放出來的時候才決定。
- C 版放出物品時，會重算一部分欄位（例如武器的傷害、護具的防護、大部分物品的價格），所以檔案裡寫的值有些只是起點。下面的表有註明。
- 舊版的 `action_description`、`cost_per_day` 已經拿掉了，新系統也不會用。寫了會被當成不認得的欄位。

## resets（重置）

重置就是區域「重新整理」時要做的事：把生物放進房間、給生物物品和裝備、把物品放進房間、設定門一開始的狀態。
欄位是照舊版的 `#RESETS` 整理出來的，之後會刪掉用不到的。

- 遊戲還不會做重置，現在只檢查寫法：`cmd` 認不認得、欄位要剛好、數字要是整數、號碼要是正整數。
- 號碼指到的房間、生物、物品存不存在，`G` 前面有沒有 `M`，`D` 的出口有沒有門，都還沒檢查。
- `resets` 是一個清單，**照順序執行**。`G` 是對「前面最近的那一筆 `M`」放出來的生物做事；那筆 `M` 沒放出生物（例如已經滿了），後面的 `G` 也不會做。
- 舊版的 `E`（讓生物穿裝備，`wear_loc` 寫 100 時是給坐騎）已經拿掉了：生物不穿裝備，也沒有坐騎。寫了會被當成不認得的指令。
- 每一筆都有 `cmd`（哪一種指令）和 `comment`（註解，給人看的，可以寫空字串 `""`）。
- 號碼欄位（`room_vnum`、`mob_vnum`、`obj_vnum`、`container_vnum`）的寫法見[號碼規則](#號碼規則)。

| cmd | 做什麼 | 其他欄位 |
|---|---|---|
| `M` | 把生物放進房間 | `rare`、`mob_vnum`、`limit`、`room_vnum` |
| `G` | 給前面最近的 `M` 那隻生物一件物品。如果那隻生物是店主，這件就是店裡賣的東西，賣不完 | `rare`、`obj_vnum`、`limit` |
| `O` | 把物品放進房間。區域裡沒有玩家、房間裡也還沒有這件物品時才會放 | `if_flag`、`obj_vnum`、`limit`、`room_vnum` |
| `P` | 把物品放進容器（容器是另一件物品）。容器裡還沒有這件物品時才會放 | `if_flag`、`obj_vnum`、`limit`、`container_vnum` |
| `D` | 設定門一開始的狀態。被撞壞的門會維持壞的 | `if_flag`、`room_vnum`、`direction`、`state` |
| `R` | 把房間前幾個方向的出口隨機對調（舊版做迷宮用的） | `if_flag`、`room_vnum`、`exit_count` |
| `*` | 整行註解，什麼都不做 | 只有 `comment` |

| 欄位 | 意思 |
|---|---|
| `rare` | 稀有度。`0`～`10` 是一定會出現；大於 10 是稀有，出現的機率大約是 (`rare` − 10) ÷ 10000，例如 `5010` 大約是 50%。`M` 的生物是稀有的話，C 版還會讓牠用 `where` 看不到。之後算生物的經驗值也會用到它（見生物的 `exp`） |
| `limit` | 最多幾隻。生物會待在原地（act 有 sentinel）時，算這個房間裡有幾隻；不然算整個遊戲裡有幾隻。只有 `M` 會用到，`G`、`O`、`P` 的 C 版讀了沒用到 |
| `if_flag` | C 版讀了沒用到 |
| `mob_vnum` | 要放的生物 |
| `room_vnum` | 哪一間房 |
| `obj_vnum` | 哪一件物品 |
| `container_vnum` | 要放進哪一件容器 |
| `direction` | 哪一個方向的出口，寫法同出口：`north`、`east`、`south`、`west`、`up`、`down` |
| `state` | 門的狀態：`0` 開著、`1` 關著、`2` 關著而且鎖著 |
| `exit_count` | 打亂前幾個方向，照北、東、南、西、上、下的順序算，`0`～`6`。例如 `2` 是北和東兩個方向的出口隨機對調 |

## 檢查區域檔

寫完或改完區域檔，可以先用檢查工具確認格式對不對，不用開伺服器：

```sh
uv run python -m mud.areacheck                     # 檢查 areas/ 裡全部的區域檔
uv run python -m mud.areacheck areas/test.json     # 只檢查一個檔案
```

- 工具會照這份手冊檢查**每一個欄位**，把所有問題一次列出來，每一行都寫出是哪個檔案、哪一間房間、哪個欄位。
- 欄位要剛好：少了欄位、或多了這份手冊沒有的欄位（例如已經拿掉的 `door_flags`），都算錯。
- 只檢查一個檔案時，通到別的區域的出口，會去同一個資料夾的其他檔案找那間房。
- 伺服器開機時也用同一套規則檢查，所以工具說沒問題的檔案，伺服器一定載入得了。
- `key` 指到的物品存不存在，目前還不會檢查。

輸出的樣子：

```
✗ areas/broken.json：2 個問題
  - broken.json：房間 1 的 sector 要寫 0～10 的整數，不能是 12
  - broken.json：房間 2 往 south 的出口指到不存在的房間 107
檢查了 1 個檔案，共 2 個問題
```

## 顏色代碼

在文字裡寫代碼，送給玩家時會換成顏色，色碼跟 C 版一樣。

| 代碼 | 顏色 | 代碼 | 顏色 |
|---|---|---|---|
| `{r` | 紅 | `{R` | 亮紅 |
| `{g` | 綠 | `{G` | 亮綠 |
| `{y` | 棕 | `{Y` | 黃 |
| `{b` | 藍 | `{B` | 亮藍 |
| `{m` | 紫 | `{M` | 亮紫 |
| `{c` | 青 | `{C` | 亮青 |
| `{w` | 灰 | `{W` | 白 |
| `{D` | 深灰 | `{x` | 回到原本的顏色 |

- 要印出 `{` 本身，就寫 `{{`。
- 換了顏色，記得在後面用 `{x` 換回來，不然後面的字都會是那個顏色。
- 顏色不能一層包一層：`{x` 一律回到原本的顏色，不會回到外層的顏色。

例如 `"description": "牆上有一行{R紅色{x的字。\n"`，「紅色」兩個字會變成亮紅色。
