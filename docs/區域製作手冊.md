# 區域製作手冊

這份手冊說明 `areas/` 裡區域檔的寫法，以及每個欄位的意思。範例以 `areas/test.json` 為準。

每個欄位都標了新系統（這個 Python 伺服器）實作了沒：
- ✅ 已實作：伺服器已經在用。
- 🔍 只檢查格式：載入時會檢查寫得對不對，但遊戲裡還沒有效果。
- ⏳ 還沒做：伺服器載入時不會讀它。
- 🔒 保留：先留著，之後再設計。

## 基本規則

- 區域檔放在 `areas/` 資料夾，副檔名是 `.json`，用 UTF-8 存檔。
- 伺服器開機時會檢查 `areas/` 裡全部的區域檔。世界區域馬上建好，動態區域和副本區域等到要用時才建立，見[三種區域](#三種區域)。
- 區域檔有錯時，伺服器會說明是哪個檔案、哪一間房間錯了，然後停止開機。會報錯的情況有：
  - 格式不對
  - 少了欄位，或多了這份手冊沒有的欄位
  - 號碼重複
  - 出口通到不存在的房間
  - 出口走進副本，或從副本走出去
  - 門只寫在一邊，見[門](#門)
  - 固定裝備（寫了加成的物品）放出來時，點數超過上限，見[affects](#affects加成)
  - 物品同時寫了主手和副手，見[wear_flags](#wear_flags拿起來穿在哪裡)
  - 武器的種類不對、種類和雙手對不上、用了怪物專用的攻擊方式，見[武器種類](#武器種類)
- 手冊裡照 C 版寫的「每個 tick」是 C 版的 tick，等於遊戲裡 1 小時，也就是新系統的 30 tick（30 秒）。新系統一個 tick 是 1 秒，見[定時做的事](玩家角色手冊.md#定時做的事)；這些功能做的時候，再定每幾個 tick 做一次。
- 文字裡要換行就寫 `\n`。描述的最後最好也加 `\n`；沒加的話，伺服器會自己補上。
- 房間名稱、房間描述、出口描述、可細看的東西的描述，都可以用[顏色代碼](#顏色代碼)。

## 號碼規則

- 每個區域檔有一個 `area_number`，寫在 `area.header` 裡。
- 檔案裡的房間、物品、生物號碼，各自只能是 **1～99**，所以一個區域最多 99 間房、99 種物品、99 種生物。
  三種號碼分開算：房間 101 和生物 101 可以同時存在。
- **遊戲裡的號碼 ＝ `area_number` ＋ 檔案裡的號碼**。例如 `area_number` 是 3200，物品 3 在遊戲裡就是 3203。
- 遊戲號碼 1～99 是保留的，不能使用，所以 `area_number` 不能是 0。算出來小於 100 就會報錯。
- `area_number` 不一定要是 100 的倍數，但算出來的遊戲號碼不能跟別的區域重複。
- 要指到某個房間、物品或生物時，例如出口的 `to_room`、門的鑰匙 `key`、回城的 `recall`、生物掉落表 `drops` 的 `obj_vnum`、
  重置的 `room_vnum`、`mob_vnum`、`obj_vnum`、`container_vnum`，都有兩種寫法：
  - 寫 **1～99**：代表同一個區域裡的房間或物品，伺服器會自動加上 `area_number`。
  - 寫 **100 以上**：代表完整的遊戲號碼，用來指到別的區域。

  例如 `test.json` 的 `area_number` 是 100，房間 1 北邊的出口寫 `"to_room": 2`，實際上就是通到 102 號房間。
  `key` 另外還可以寫 `-1` 或 `0`，代表不用鑰匙。

## 三種區域

`header.type` 寫這個區域是哪一種：

| type | 名稱 | 什麼時候建立 | 什麼時候釋放 |
|---|---|---|---|
| world | 世界區域 | 伺服器開機時 | 不釋放 |
| dynamic | 動態區域 | 第一個玩家走進去時 | 裡面沒有玩家超過 20 分鐘 |
| instance | 副本區域 | 用 `enter` 走進傳送門時 | 裡面沒有玩家超過 20 分鐘 |

- **世界區域**：全部的世界區域合起來是一個世界。玩家登入後站在世界區域裡。
- **動態區域**：
  - 從世界區域（或別的動態區域）的出口走進去。
  - 大家進到同一份，不分隊伍。
  - 釋放之後，下一個人走進去會重新建立，裡面的東西全部重來。
- **副本區域**：
  - 只能用 `enter 傳送門名字` 進去，用 `recall` 出來。所以下面兩種寫法都會報錯：
    - 別的區域的出口通到副本裡。
    - 副本的出口通到別的區域。
  - 擁有者是隊長，同隊的人進到同一份。沒有同隊的人，就算同時 `enter`，也是各自一份。
  - 同一個副本檔可以同時開好幾份，每一份都是獨立的。
  - 在副本裡死掉，會回到這份副本的 1 號房。
  - 新系統：伺服器已經能建立和釋放副本；`enter`、`recall`、傳送門、組隊、死亡還沒做。

### room_flags（房間旗標）

可以寫數字，也可以寫字串：
- 數字：`0`、`5`
- 字串：`"0"`、`"5"`、`"1|4"`

`|` 的意思是把幾個旗標合在一起。例如 `"1|4"` 代表「很暗」加上「怪物不會走進來」，等於 `5`。合起來不是相加：`"1|3"` 是 3，不是 4。不需要任何旗標時寫 `0`。

|---|---|---|
| 1 | dark | 很暗 |
| 4 | no_mob | 怪物不會走進來 |
| 8 | indoors | 室內 |
| 16 | underground | 地底：吸血鬼白天在這裡不怕陽光 |
| 32 | clanrest_lv1 | 幫派休息室（第 1 級） |
| 64 | clanrest_lv2 | 幫派休息室（第 2 級） |
| 128 | clanrest_lv3 | 幫派休息室（第 3 級） |
| 256 | clanroom | 幫派房間：只有這個幫派的人能進來 |
| 512 | private | 私人房間：最多 2 個人 |
| 1024 | safe | 安全區：不能戰鬥 |
| 2048 | solitary | 單人房：最多 1 個人 |
| 4096 | pet_shop | 寵物店 |
| 8192 | no_recall | 不能用回城 |
| 16384 | cone_of_silence | 不能說話（頻道和 tell 都不能用） |
| 32768 | no_murder | 不能殺玩家 |
| 65536 | fen | 沼氣：不會飛的人會中毒 |

### exits（出口）

`exits` 的 key 是方向，只能用這六個：`north`、`east`、`south`、`west`、`up`、`down`。每個方向寫一個出口：

| 欄位 | 意思 | 新系統 |
|---|---|---|
| `description` | 往這個方向看到的樣子。玩家打 `look n`、`look north` 時顯示這段文字，不是隔壁房間的描述。可以寫空字串 `""`，這時會顯示「那裡沒有什麼特別的東西。」 | ✅ 已實作 |
| `keywords` | 門的名字，多個名字用空白隔開，例如 `"鐵門 gate"`。只有有門的出口才用得到，沒有門就寫 `""` | ✅ 已實作 |
| `locks` | 門的種類，見下表 | ✅ 已實作（撬、撞、穿門術還沒做） |
| `key` | 開這扇門要用的鑰匙（物品號碼）。寫法同 `to_room`：1～99 是這個區域的物品，100 以上是別的區域的完整號碼。寫 `-1` 或 `0` 代表不用鑰匙。鑰匙在背包裡或身上都算 | ✅ 已實作 |
| `to_room` | 通到哪一間房，寫法見[號碼規則](#號碼規則) | ✅ 已實作 |

`locks` 的值：

| locks | 意思 |
|---|---|
| 0 | 沒有門 |
| 1 | 門 |
| 2 | 門，撬不開 |
| 3 | 門，撞不開 |
| 4 | 門，撬不開也撞不開 |
| 5 | 門，法術穿不過去 |
| 6 | 門，撬不開、法術穿不過去 |
| 7 | 門，撞不開、法術穿不過去 |
| 8 | 門，撬不開、撞不開、法術穿不過去 |

- 撬：pick 指令；撞：bash 指令；法術穿過去：穿門術（pass door）。這三個還沒做（要等技能），現在 1～8 用起來都一樣。
- 門一開始是開著、關著還是上鎖，不在這裡設定，由重置的 [`D`](#resets重置) 決定。沒有 `D` 的門一開始是開著的。

### 門

- **門兩邊都要寫**：房間 A 往北的出口有門，通到房間 B；B 往南的出口如果指回 A，也要有門（`locks` 不是 0），不然檢查會報錯。
  兩邊是同一扇門：在一邊打開、關上、上鎖、開鎖，另一邊跟著變。
  - 兩邊的名字、種類、鑰匙可以不一樣，各算各的（例如牢房裡面沒有鑰匙孔）。
  - B 沒有往南的出口（單向出口），或往南的出口指到別間，就不算同一扇門，不用寫。
  - 舊區域轉過來時，只寫了一邊的門（A 有門通到 B，B 的反方向出口指回 A，但沒有門）：轉換時自動在 B 那一邊補上門，
    名字（`keywords`）、種類（`locks`）、鑰匙（`key`）照 A 那一邊寫；B 那個出口自己的 `description` 不變。
    B 的反方向沒有出口、或指到別間，照上面的規則不算同一扇門，不用補。
    （area2json 照檔案原樣存，不會補；是之後轉成伺服器格式那一步做的。）
- 門的名字用 `keywords` 的第一個字，例如 `"木門 door"` 是「木門」；沒寫 `keywords` 就叫「門」。
- 玩家的指令（休息時也能用，睡覺不行）：

  | 指令 | 做什麼 |
  |---|---|
  | `open 木門`（o） | 打開。鎖著的門要先開鎖 |
  | `close 木門`（cl） | 關上 |
  | `lock 木門`（loc） | 上鎖。門要先關上，身上要有鑰匙 |
  | `unlock 木門`（un） | 開鎖。門要關著，身上要有鑰匙 |

  - 指定門：先找門的名字（要整個字一樣，英文不分大小寫），找不到再當成方向（`n`、`no`、`north` 都算北）。
  - `key` 是 `-1` 或 `0` 的門鎖不起來，也打不開鎖：被重置鎖上的這種門，只能等下一次重置（之後還有撬、撞）。
  - 鑰匙是物品：背包裡或身上有那個號碼的物品，就能上鎖、開鎖。
  - 地上或身上的容器也用這四個指令開關、上鎖，見[容器旗標](#容器旗標)。找的順序：門的名字 → 方向 → 東西（所以 `open n` 一定是北邊的門）。
- 門關著還要走過去：有寫 `keywords` 就顯示「【木門】關起來了。」；沒寫 `keywords` 就用方向，例如「北方關起來了。」
- 看得到門：房間標題的出口，關著的門是紫色的 `*北`；`look 北` 會在描述後面加一行「木門是關著的。」或「木門是開著的。」
- **對面房間看得到**：門被打開、關上（之後還有被撞開）時，對面房間醒著的人會看到「南方的木門被打開了。」（方向和名字照對面那一邊寫的）。
  對面房間很暗（`room_flags` 有 `1 dark`）就要有光源才看得到。光源是物品，還沒做，所以現在很暗的房間看不到。
  上鎖、開鎖對面不會知道（照 C 版）。

### extra_descriptions（可以細看的東西）

一個清單，每一項是一樣可以細看的東西：

| 欄位 | 意思 | 新系統 |
|---|---|---|
| `keywords` | 名字，多個名字用空白隔開，例如 `"牌子 sign"`。不能是空的 | ✅ 已實作 |
| `description` | 細看時顯示的文字 | ✅ 已實作 |

- 玩家打 `look 牌子` 或 `look sign` 就會看到 `description`。
- 名字要打完整：打 `look 牌` 找不到「牌子」。英文不分大小寫，`look SIGN` 也可以。
- `look` 會先找東西，再找方向。所以如果有東西取名叫 `north`，`look north` 會看到那樣東西，而不是北邊的出口。取名時要避開方向的英文。
- 沒有東西可以細看時，寫空清單 `[]`。

### script

房間和生物的腳本用 Lua 寫，區域檔只寫用哪個 `.lua` 檔，例如 `{"file": "鐘聲.lua", "timer": 60}`，見[腳本](#腳本)。沒有腳本時寫 `null`。

物品的 `script` 還是舊的格式（物品的腳本還沒做，之後也會改成 Lua）：

```json
"script": {
  "trigger": {"value": 64, "names": ["say"]},
  "function": "os_test_sword"
}
```

## mobiles（生物）

生物就是怪物、商人、守衛這些不是玩家的角色。欄位是照舊版區域檔整理出來的，之後會刪掉用不到的。

- 生物照[重置](#resets重置)的 `M` 出現在房間裡，出現時就照等級、種類、攻擊類型、攻防傾向、原型算好全部屬性（`mud_design` 設計文件 §4.1～§4.3），HP 補滿。
  戰鬥、走動、商店、說話這些還沒做。怪物的 MP、MV 是 0（放技能不耗資源，技能系統再定）。
- 現在只檢查寫法：欄位要剛好、數字要是整數、文字要是字串。數字代表什麼（例如旗標有沒有這一格）還沒檢查。
- 「C 版讀了就丟」是說 C 版的程式讀了這個欄位以後，連存都沒存。
- 舊版的 `hitroll`、`ac`、`hit_dice`、`damage_dice`、`gold`、`custom`（K 行）、`exp` 已經拿掉了，新系統也不會用。寫了會被當成不認得的欄位。
- 舊版的 A 行（`actions`，平常的動作）、F 行（`fight_actions`，戰鬥中的動作）也拿掉了（使用者定的：生物做事只留 [special](#special特殊程式) 和腳本，寫了一樣是不認得的欄位）。
  舊區域都會重寫，這兩種和舊的 C 腳本都不轉，重寫時用腳本寫。
  經驗值照 `mud_design` 設計文件 §4.7 算（看怪物種類和等級差），不在生物身上寫倍數。

| 欄位 | 意思 | 新系統 |
|---|---|---|
| `vnum` | 檔案裡的生物號碼，只能是 1～99，見[號碼規則](#號碼規則) | 🔍 只檢查格式 |
| `keywords` | 玩家用來指定牠的名字，多個名字用空白隔開，例如 `"merchant 商人"`。不能是空的 | ✅ 已實作（`kill`、`use`… 只要打任何一個名字的開頭，例如 `kill mer`；同名的用 `2.merchant` 指定畫面上第 2 隻） |
| `short` | 短名稱，例如 `"測試商人"`。不能是空的。生物的名字就是它（不是站著時，房間裡寫「測試商人躺在這裡睡覺。」） | ✅ 已實作 |
| `long` | 在房間裡看到牠時顯示的那一行（站著的時候，亮白）。舊區域的寫法是「一位測試商人/merchant/站在櫃檯後面。」 | ✅ 已實作 |
| `description` | 用 `look` 看牠時顯示的描述 | 🔍 只檢查格式 |
| `level` | 等級。照寫的值，每次出現都一樣，不隨機加減（不照 C 版載入時的 ±1）；想要變化用 [tier_roll](#tier_roll重生時骰種類) | ✅ 已實作（生物出現時照它算好全部屬性，打起來就用這些屬性） |
| `tier` | 種類，**一定要寫**：`trash`、`normal`、`elite`、`boss`，見[tier](#tier種類)。屬性和經驗值由等級和種類算出來 | ✅ 已實作（生物出現時照它算好全部屬性，打起來就用這些屬性；打死牠的經驗值也看它；look 的標記見[tier](#tier種類)） |
| `tier_roll` | 重生時變成其他種類的機率，見[tier_roll](#tier_roll重生時骰種類)。寫 `null` 是固定 `tier`，不會變 | ✅ 已實作 |
| `attack` | 攻擊類型，見[attack](#attack攻擊類型)。寫 `null` 是純物理 | ✅ 已實作（生物出現時照它算好全部屬性，打起來就用這些屬性） |
| `defense` | 攻防傾向，見[defense](#defense攻防傾向)。寫 `null` 是標準 | ✅ 已實作（生物出現時照它算好全部屬性，打起來就用這些屬性） |
| `archetype` | 原型，見[archetype](#archetype原型)。寫 `null` 是標準 | ✅ 已實作（生物出現時照它算好全部屬性，打起來就用這些屬性） |
| `act` | 行為旗標，寫法同 `room_flags`（數字或 `"2\|64"`），見[act](#act行為旗標) | 🔍 只檢查格式（只有 2 sentinel 用到：重置的 `limit` 怎麼算） |
| `affected_by` | 身上帶著的效果，寫法同 `room_flags`，見[affected_by](#affected_by身上的效果) | 🔍 只檢查格式 |
| `alignment` | 陣營，-1000（邪惡）～1000（善良） | 🔍 只檢查格式 |
| `race` | 種族名稱，例如 `"human"`，見[race](#race種族)。C 版比對名稱的開頭，不分大小寫 | 🔍 只檢查格式 |
| `sex` | 性別：0 中性、1 男、2 女 | ✅ 已實作 |
| `position` | 姿勢，見[position](#position姿勢)。生物出現時就是這個姿勢（C 版讀了就丟，新系統會用，可以做睡著的生物）；寫錯就站著 | ✅ 已實作 |
| `drops` | 掉落表：死掉時可能掉出的物品，見[drops](#drops掉落表)。沒有掉落寫 `[]` | ✅ 已實作 |

### tier（種類）

怪物的屬性由程式照「等級 ＋ 種類」算出來（`mud_design` 設計文件 §4.1、§4.3），區域檔不寫 HP、傷害這些數值。
經驗值也照等級和種類算（設計文件 §4.7）。

| tier | 種類 | 裝備完整度 | 經驗加成 |
|---|---|---|---|
| trash | 垃圾怪 | ×0 | ×0.1 |
| normal | 一般怪 | ×0.5 | ×1.2 |
| elite | 菁英怪 | ×1 | ×1.1 |
| boss | Boss 怪 | ×1.1 | ×1.0 |

- 裝備完整度 ×1 的怪，對穿滿同級最佳裝備的玩家單挑是 1:1。
- 多隻同時攻擊很危險：同級的一般怪 2 隻就打不贏。要讓玩家一次拉 2 隻，用低幾級的怪。
- 玩家 `look` 時，菁英怪的名字前面標亮綠的「(菁英)」，Boss 怪標亮紅的「(首領)」（照牠出現時骰到的種類，`tier_roll` 骰成 boss 就是首領）；一般怪、垃圾怪沒有標記。例如「(菁英)一位測試商人/merchant/站在櫃檯後面。」

### attack（攻擊類型）

| attack | 意思 |
|---|---|
| phys | 物理 |
| spell | 法術 |
| dragon | 龍焰（只有怪物有） |

- 寫 `null`：純物理。
- 只用一種：寫一個代號，例如 `"spell"`。
- 主／次搭配：寫成 `"主/次"`，例如 `"dragon/phys"` 是主龍焰、次物理，每次攻擊 70% 用主的、30% 用次的。兩個不能一樣。
- 不管怎麼搭，總戰力都不變，差別只在玩家的抗性配裝對誰有效（設計文件 §4.1）。
- 帶龍焰的怪，玩家沒有龍焰抗性幾乎打不贏（設計文件 §5.5）。

### defense（攻防傾向）

把物理抗性和法術抗性的點數搬來搬去，總點數不變。寫 `null` 是標準（設計文件 §4.1、§4.2）。

- 擅長的抗性 : 不擅長的抗性 ＝ 2 : 0.5，再換算回原本「物抗 ＋ 法抗」的合計，所以總點數不變：
  合計 ＝ 物抗 ＋ 法抗；擅長的 ＝ 合計 × 2 ÷ 2.5，不擅長的 ＝ 合計 × 0.5 ÷ 2.5。
- 套在怪物整個物抗、法抗上（不只可調的 25%），可以跟 [archetype](#archetype原型) 一起用。
- 物抗、法抗原本一樣時，就是 ×1.6、×0.4：

| defense | 物抗 | 法抗 | 意思 |
|---|---|---|---|
| phys | ×1.6 | ×0.4 | 怕法術，例如石魔 |
| spell | ×0.4 | ×1.6 | 怕物理 |

### archetype（原型）

把可調的點數重新分配，總點數不變（設計文件 §4.2）。寫 `null` 是標準。不管怎麼調，都不會比標準強。

- 只動怪物「可調的 25%」那部分（含進度加成），75% 的固定基礎不動。
- 表上的 ×2、×0.5 是比例：可調點數先照標準比例分到各次要屬性，再把列到的屬性乘上係數，沒列到的 ×1。
- 乘完以後，把全部可調點數一起換算回原本的合計（例如乘完變成原本的 1.2 倍，每一項就都 ÷ 1.2），所以總點數不變。
- `extreme_tank` 是特例：可調的 25% 全部放 HP。
- 跟 [defense](#defense攻防傾向) 一起用時，先套 archetype，再拿那時候的物抗 ＋ 法抗合計套 defense。

| archetype | 原型 | 怎麼分 |
|---|---|---|
| tank | 坦克 | HP、抗性、閃躲 ×2；攻擊類 ×0.5 |
| berserker | 狂戰 | 傷害、攻速、爆擊 ×2；HP、抗性、閃躲 ×0.5 |
| agile | 敏捷 | 閃躲、命中、攻速 ×2；HP、抗性 ×0.5 |
| extreme_tank | 極端坦克 | 可調的 25% 全部放 HP |

### tier_roll（重生時骰種類）

`tier` 是基本種類。`tier_roll` 寫「變成其他種類的機率」，每次重生骰一次（設計文件 §4.9）。

- 寫成 `{種類: 機率}`，機率以萬分之一為單位：`100` 是 1%、`2000` 是 20%。
- 例如 `tier` 是 `normal`，`tier_roll` 寫 `{"elite": 2000, "boss": 100}`：79% 是一般怪、20% 是菁英、1% 是 Boss。
- 寫 `null`：固定是基本種類，不會變。
- 不用寫基本種類自己；機率加起來不能超過 `10000`（100%），剩下的就是基本種類。
- 先看重置的出現機率（`rare`）決定出不出現，出現了才骰種類。骰到的種類決定這一隻的強度和經驗值。

### drops（掉落表）

死掉時可能掉出的物品，一行一件，**每一行各自骰**，所以一隻怪可能同時掉好幾件（設計文件 §4.10）。沒有掉落寫 `[]`。
原本的 `random_drop`（只能掉一件、沒有顏色）已經改用這張表。

例如 `{"obj_vnum": 2, "color": "orange", "chance": 100, "tiers": ["boss"]}`：這隻怪骰到 Boss 時，死掉有 1% 機率掉出橘色的物品 2。

| 欄位 | 意思 |
|---|---|
| `obj_vnum` | 掉出的物品號碼，寫法見[號碼規則](#號碼規則)，照**這隻生物所在的區域檔**換算（別的檔用 `M` 放牠也一樣）。這個物品存不存在，目前還不會檢查：死掉時找不到就不掉，伺服器記一筆 log |
| `color` | 裝備的顏色，見下表。不是裝備的物品（藥水、鑰匙…）寫 `null` |
| `chance` | 機率，以萬分之一為單位：`100` 是 1%、`10000` 是 100% |
| `tiers` | 骰到哪些種類才會掉，例如 `["boss"]`、`["elite", "boss"]`。寫 `null` 是所有種類都會掉 |

掉出來的裝備，等級是這隻怪的等級；屬性照設計文件 §3.3 的隨機裝備規則抽，可配的點數是該等級、該部位的上限乘上顏色的加成。
寫了 `affects` 的是固定裝備，用寫好的屬性，不隨機抽。掉出來的物品放在[屍體](#屍體)裡。

| color | 顏色 | 點數加成 | 遊戲裡名字的顏色 |
|---|---|---|---|
| gray | 灰 | ×0（沒有屬性） | 暗灰 |
| white | 白 | ×1 | 亮白 |
| blue | 藍 | ×1.2 | 亮藍 |
| purple | 紫 | ×1.3 | 亮紫 |
| orange | 橘 | ×1.4 | 暗黃（終端機沒有橘色） |

沒寫顏色（`null`）和不是裝備的物品，名字是亮綠（照 C 版）。名字後面接 `keywords` 裡的英文字，用亮青（照 C 版），例如「測試藥水/potion」；
`keywords` 沒有英文字就只有名字。

### 屍體

生物死掉時，原地留下一具屍體（物品種類 23 怪物屍體，遊戲自己做的，區域檔不用寫）。照 C 版：

- 名字是「野狗的屍體」，地上看到亮白的「野狗的屍體橫躺在地上。」，後面接亮青的「/corpse」（跟其他物品一樣），玩家用 `corpse` 或 `屍體` 指它。
- 掉落表骰到的物品放在屍體裡，照掉落表的順序；生物身上帶的東西（重置 `G` 給的）也放進去，**店主身上的不會**：會直接消失（照 C 版，防止殺店主複製東西）。玩家用 `look in 屍體` 看裡面有什麼，用 `get all 屍體` 拿出來（屍體本身撿不起來）。
- **不管裡面有沒有東西，10～14 個 C 版 tick（約 5～7 分鐘）後就連同裡面的東西一起消失**，房間裡醒著的人會看到「野狗的屍體腐爛變成了灰塵。」
- 動態區域、副本釋放時，裡面的屍體、物品、生物全部一起消失。每份副本的屍體各自分開。
- 隨機裝備的名稱接在物品名字前面，例如物品叫「長劍」、抽到主詞綴 STR、次詞綴攻速，就是「疾風之蠻力長劍」。灰色、沒寫顏色的沒有隨機屬性，名字不變。
- 生物身上 `G` 給的物品（C 版會放進屍體，店主賣的東西不會）等 `G` 做了再做。

### shop（商店）

舊版的 `#SHOPS`，店主就是這隻生物。

| 欄位 | 意思 |
|---|---|
| `buy_types` | 會收購的物品種類，見[物品種類](#item_type物品種類)。C 版最多 5 種 |
| `profit_buy` | 玩家向牠買東西時的價格倍率（%） |
| `profit_sell` | 玩家賣東西給牠時的價格倍率（%） |
| `open_hour` | 開店時間（遊戲裡的幾點） |
| `close_hour` | 關店時間 |

商店的價格（設計文件 §3.7）：

- 商店價格 ＝ 基本價格 × 這家店的倍率：玩家買 × `profit_buy`%，玩家賣 × `profit_sell`%。人類再乘上種族技能「交易」（見[玩家角色手冊](玩家角色手冊.md#種族)）。
- 基本價格：裝備是點數，其他物品是 `cost`，見[物品](#objects物品)的 `cost`。
- **賣給商店拿到的錢，最多等於這個人向這家店買同一件東西要付的錢**，所有人都適用。所以買了馬上賣回去，最多不賺不虧；正常的店不會用到這條。
- 原因：舊版區域檔 181 家店裡有 62 家，沒有這條的話，人類可以靠買賣刷錢。其中 6 家的收購價比賣價還高，連其他種族都能刷。

## objects（物品）

物品就是裝備、藥水、鑰匙、容器這些東西。欄位是照舊版的 `#OBJECTS` 整理出來的，之後會刪掉用不到的。

- 現在只有[掉落表](#drops掉落表)放出來的物品會出現在遊戲裡（在[屍體](#屍體)裡）。物品要放在哪裡，寫在[重置](#resets重置)的 `O`、`P`、`G`，這三個還沒做。
- 現在只檢查寫法：欄位要剛好、數字要是整數、文字要是字串、`values` 要剛好 4 個。數字代表什麼（例如種類有沒有這一種）還沒檢查。
- 物品沒有等級欄位：C 版的物品等級是放出來的時候才決定。
- C 版放出物品時，會重算一部分欄位（例如武器的傷害、護具的防護、大部分物品的價格），所以檔案裡寫的值有些只是起點。下面的表有註明。
- 舊版的 `action_description`、`cost_per_day` 已經拿掉了，新系統也不會用。寫了會被當成不認得的欄位。

| 欄位 | 意思 | 新系統 |
|---|---|---|

### affects（加成）

舊版的 A 行。每一項寫 `{"location": 位置, "modifier": 數值}`，例如 `{"location": 1, "modifier": 2}` 是力量 +2、`{"location": 7, "modifier": 3}` 是物理傷害 +3。

- 0～5 是主屬性，代號是 C 版的名稱。
- 6～15 是 10 種可以用裝備點數買的次要屬性，代號跟 `mud_design` 設計文件的程式一樣。主屬性、次要屬性這些名詞見[玩家角色手冊](玩家角色手冊.md#名詞)。區域作者可以用它們做固定屬性的裝備（任務獎勵、Boss 專屬……）。
- 舊區域的 `location` 數字意思不一樣（例如舊的 13 是生命），轉檔時不沿用，要照這張表重新寫。
- **寫了 affects 的物品是固定裝備**（例如任務獎勵、Boss 專屬）：放出來時用作者寫的，不隨機抽。`affects` 是 `[]` 的裝備，放出來時才照等級和顏色隨機抽（設計文件 §3.3）。
- 固定裝備的點數不能超過「放出來的等級、部位的上限 × 顏色加成」，超過會報錯。等級和顏色看放出它的地方：掉落表用那隻生物的等級和那一行的顏色，重置 `G`、`O`、`P` 用自己的 `level`、`color`（`G` 沒寫等級就用前面那筆 `M` 的生物等級）。灰色和沒寫顏色（`null`）的加成是 ×0，只放得進不算點數的龍焰抗性。
- 點數 ＝ 每一項的數值 × 單價：主屬性跟著等級長（1 級力量 +1 大約 3.74 點），物理、法術傷害 10，龍焰抗性 0，其他次要屬性 1（設計文件 §3.1、§3.2）。
- 加成可以是負的，例如力量 +3、敏捷 -1（`{"location": 2, "modifier": -1}`）。負的會抵掉點數：正負加起來不超過上限就好（設計文件 §3.4）。
  - 要自己把關：公會用不到的屬性寫負的，等於白拿點數。例如給杖之公會用的裝備寫物理傷害 -1，就多出 10 點能放別的屬性。
- 部位的上限看等級：例如 1 級頭盔大約 5.7、主手大約 14.3；雙手武器是主手加副手；戒指一枚是一半；持握、光源是 0（設計文件 §3.3 的表，守則見 §3.4）。穿戴位置有好幾個時，用上限最大的那個（主手和副手不能同時寫，見[wear_flags](#wear_flags拿起來穿在哪裡)）。
- 16 龍焰抗性**不算點數**，不計入上限。玩家身上本來沒有，要由區域作者另外給（例如龍系區域的任務獎勵、專屬裝備）。
  給到「參考值 ＋ 全身 AC」打龍焰怪才是 1:1，例如 Lv10 大約 99、Lv50 大約 646；沒給的話，打龍焰怪幾乎都會輸（設計文件 §5.5）。

## resets（重置）

重置就是區域「重新整理」時要做的事：把生物放進房間、給生物物品和裝備、把物品放進房間、設定門一開始的狀態。
欄位是照舊版的 `#RESETS` 整理出來的，之後會刪掉用不到的。

- `M`、`G`、`O`、`P`、`D`、`R` 都做了。
- `G` 給的東西放進生物的背包。生物被打死時放進屍體；**店主的會直接消失**（照 C 版，店裡賣的東西不能靠殺店主拿到）。
- `P` 的容器是這份區域裡**第一件**那個號碼的物品：地上的，或生物身上帶的（例如 `G` 給的袋子）。找不到就跳過、在伺服器視窗記一筆警告。
- `R` 對調出口時，出口的描述、門也一起換；對面的房間不動，所以走過去不一定走得回來（舊版做迷宮用的）。
- **什麼時候重置**（照 C 版）：區域建立時做一次（世界是開機時，動態區域是有人走進去時，副本是建立時）。
  之後每 1 分鐘看一次每個區域檔：區域檔的房間裡沒有玩家，大約 3 分鐘重置一次；有玩家，大約 15 分鐘重置一次。
  有玩家時，重置前 1 分鐘醒著的玩家會聽到「你聽到一陣腳步聲。」
- 重置會補回少掉的生物（例如被打死的），已經有 `limit` 隻就不放。
- 重置也會把門設回 `D` 寫的狀態，玩家打開的門會再關起來（照 C 版）。
- 號碼指到的房間、生物、物品存不存在，`G` 前面有沒有 `M`，`D` 的出口有沒有門，都還沒檢查。
- `resets` 是一個清單，**照順序執行**。`G` 是對「前面最近的那一筆 `M`」放出來的生物做事；那筆 `M` 沒放出生物（例如已經滿了），後面的 `G` 也不會做。
- 舊版的 `E`（讓生物穿裝備，`wear_loc` 寫 100 時是給坐騎）已經拿掉了：生物不穿裝備，也沒有坐騎。寫了會被當成不認得的指令。
- 每一筆都有 `cmd`（哪一種指令）和 `comment`（註解，給人看的，可以寫空字串 `""`）。
- 號碼欄位（`room_vnum`、`mob_vnum`、`obj_vnum`、`container_vnum`）的寫法見[號碼規則](#號碼規則)。

| cmd | 做什麼 | 其他欄位 |
|---|---|---|
| `M` | 把生物放進房間 | `rare`、`mob_vnum`、`limit`、`room_vnum` |
| `G` | 給前面最近的 `M` 那隻生物一件物品。如果那隻生物是店主，這件就是店裡賣的東西，賣不完 | `rare`、`obj_vnum`、`color`、`level`、`limit` |
| `O` | 把物品放進房間。區域裡沒有玩家、房間裡也還沒有這件物品時才會放 | `if_flag`、`obj_vnum`、`color`、`level`、`limit`、`room_vnum` |
| `P` | 把物品放進容器（容器是另一件物品）。容器裡還沒有這件物品時才會放 | `if_flag`、`obj_vnum`、`color`、`level`、`limit`、`container_vnum` |
| `D` | 設定門一開始的狀態，一筆同時設定兩邊（見[門](#門)）。被撞壞的門會維持壞的（撞門還沒做） | `if_flag`、`room_vnum`、`direction`、`state` |
| `R` | 把房間前幾個方向的出口隨機對調（舊版做迷宮用的） | `if_flag`、`room_vnum`、`exit_count` |
| `*` | 整行註解，什麼都不做 | 只有 `comment` |

| 欄位 | 意思 |
|---|---|
| `rare` | 出現機率。`0`～`10` 是一定會出現；大於 10 就不一定會出現，機率大約是 (`rare` − 10) ÷ 10000，例如 `5010` 大約是 50%。`M` 的生物不一定會出現時，C 版還會讓牠用 `where` 看不到。只決定多常出現，不影響經驗值（見 `mud_design` 設計文件 §4.8） |
| `limit` | 最多幾隻。生物會待在原地（act 有 sentinel）時，算這個房間裡有幾隻；不然算同一份區域裡有幾隻（C 版是整個遊戲，新系統有副本，每份副本各自算；世界就是整個世界）。寫 `0` 就不會放。只有 `M` 會用到，`G`、`O`、`P` 的 C 版讀了沒用到 |
| `if_flag` | C 版讀了沒用到 |
| `mob_vnum` | 要放的生物 |
| `room_vnum` | 哪一間房 |
| `obj_vnum` | 哪一件物品 |
| `color` | 裝備的顏色，代號跟[掉落表](#drops掉落表)一樣：`gray`、`white`、`blue`、`purple`、`orange`。不是裝備的物品寫 `null`。顏色寫在放出物品的地方，所以同一件物品在不同地方可以是不同顏色（設計文件 §3.3） |
| `level` | 物品的等級：沒寫 `affects` 的裝備照等級和顏色隨機抽屬性；寫了的是固定裝備，用等級算點數上限（見[affects](#affects加成)）。`G` 寫 `null` 就是前面那筆 `M` 的怪物等級；店主賣的東西也一樣，要賣低等裝備就自己寫等級。`O`、`P` 沒有怪物帶著，一定要寫整數 |
| `container_vnum` | 要放進哪一件容器 |
| `direction` | 哪一個方向的出口，寫法同出口：`north`、`east`、`south`、`west`、`up`、`down` |
| `state` | 門的狀態，見下表 |
| `exit_count` | 打亂前幾個方向，照北、東、南、西、上、下的順序算，`0`～`6`。例如 `2` 是北和東兩個方向的出口隨機對調 |

`D` 的 `state`：

| state | 意思 |
|---|---|
| 0 | 開著 |
| 1 | 關著 |
| 2 | 關著而且鎖著 |

- 一筆 `D` 同時設定門的兩邊，不用寫兩筆。C 版一筆只設一邊，所以舊區域轉過來，每扇門有兩筆 `D`，後面那筆會蓋掉兩邊（通常兩筆一樣，沒差）。
- `D` 的房間或方向沒有門時，伺服器跳過這一筆、在伺服器視窗記一筆警告（還沒檢查）。
- 門通到別的區域物件（例如世界通到動態區域）時，對面的動態區域還沒有人去過就還沒建立，`D` 只設得到這一邊。這種門兩邊各寫一筆 `D`。

## 腳本

規則是使用者定的（2026-11-06）。房間和生物的腳本用 Lua 5.4 寫，關在沙箱裡。
物品的腳本這次不做，物品的 `script` 照舊（之後寫法跟這裡一樣）。

### 寫在哪

腳本是獨立的 `.lua` 檔，放在跟區域檔同名的資料夾：`areas/test.json` 的腳本放在 `areas/test/` 裡。區域檔只寫用哪個檔：

```json
"script": {"file": "鐘聲.lua", "timer": 60}
```

| 欄位 | 意思 |
|---|---|
| `file` | 用哪個 `.lua` 檔（在區域檔同名的資料夾裡）。好幾間房間、好幾隻生物可以用同一個檔，每個主人的變數照樣分開 |
| `timer` | `on_timer` 每幾秒跑一次，1～3600 的整數。沒有 `on_timer` 就寫 `null` |

```lua
-- areas/test/鐘聲.lua
function on_timer()
  room:echo("遠處傳來鐘聲。")
end
```

- 沒有腳本時 `script` 寫 `null`。檔案用 UTF-8 存（跟區域檔一樣）。
- 最外層只寫函式（`function on_say(...) ... end`），要用到的時機才寫。寫在函式外面的程式每次觸發都會跑一次。
- 開機時每個腳本先編譯一次，有下面這些就不開機，並說錯在哪：
  - 檔案不存在、不是 `.lua`、檔名跑出那個資料夾（例如 `../`）。
  - 語法錯。
  - 定義了不認得的 `on_` 開頭函式（例如打錯字的 `on_sya`）。
  - 有 `on_timer` 卻沒寫 `timer`，或有 `timer` 卻沒有 `on_timer`；`timer` 不是 1～3600。
  - 字轉不成 Big5。

### 腳本裡的名字

- `me`：這個腳本的主人。房間的腳本是那間房間，生物的腳本是那隻生物。
- `room`：主人所在的房間。房間的腳本裡，`me` 和 `room` 是同一個。
- `actor`：觸發的人（說話的、走進來的、打指令的……），玩家或生物都有可能。

### 觸發時機和參數

| 函式 | 房間 | 生物 | 什麼時候 | 參數 |
|---|---|---|---|---|
| `on_command(actor, cmd, arg)` | ✓ | ✓ | 有人在這間房裡打指令，遊戲處理之前 | `cmd`：指令的全名（打 `n` 也是 `"north"`；不是指令就是打的那個字，小寫）；`arg`：後面的字，沒有是 `""`。**`return true` 就擋住**，遊戲不再處理 |
| `on_timer()` | ✓ | ✓ | 每 `timer` 秒一次，從房間建好、生物出現開始算 | 沒有 |
| `on_give(actor, item, gold)` | | ✓ | 有人 `give` 牠東西或金幣，給完以後 | `item`：物品號碼（給金幣時是 `nil`）；`gold`：金幣數量（給東西時是 `0`） |
| `on_say(actor, text)` | ✓ | ✓ | 玩家在這間房裡 `say`，說完以後。生物說的不算（生物之間對話用 `tell`，見下面的例子） | `text`：說的話 |
| `on_death(killer)` | | ✓ | 牠倒下之前（還在房間裡，`me:command("say ...")` 留遺言做得到），跑完才留屍體、移出遊戲 | `killer`：打死牠的人（打架中被持續扣血扣死，是牠正在打的對手）；沒在打架時被扣死、`slay` 是 `nil` |
| `on_enter(actor, from)` | ✓ | ✓ | 有人走進這間房以後 | `from`：從哪個方向進來（`"south"`……）；傳送進來是 `nil` |
| `on_fight(target)` | | ✓ | 打架中每回合一次，那一回合打完以後 | `target`：牠正在打的人 |
| `on_born()` | | ✓ | 牠出現以後（重置放出來、`load_mob`） | 沒有 |
| `on_reset()` | ✓ | ✓ | 主人所在的區域檔重置以後 | 沒有 |
| `on_tell(actor, text)` | | ✓ | 有人 `tell` 牠 | `text`：說的話 |

- 號碼的寫法跟[號碼規則](#號碼規則)一樣：1～99 是這個腳本所在的區域檔，100 以上是完整號碼。腳本拿到的號碼（例如 `on_give` 的 `item`）也照這個寫法。
- 好幾個腳本同時觸發：房間的先跑，再來房間裡的生物（照進房間的先後）。`on_command` 有一個擋住，後面的就不跑。
- 腳本做的事也會觸發別的腳本（例如 `transfer` 過去會叫那邊的 `on_enter`、`load_mob` 會叫新生物的 `on_born`），但不會觸發自己
  （生物自己打的指令不會叫到自己的 `on_command`）。
- 一串：玩家的一個指令（或一次定時的事、一次 `wait` 完接著跑）引起的全部腳本。一串裡每間房間、每隻生物最多跑一次，
  所以生物 A `tell` B、B 馬上 `tell` 回 A，A 不會再跑；B 先 `wait` 再回就可以（`wait` 完是新的一串）。
- 一串最多 5 層（A 觸發 B、B 觸發 C……），再下去就不觸發，記一筆。

### 能用的函式

| 寫法 | 做什麼 |
|---|---|
| `actor:has_item(號碼)`、`actor:wears_item(號碼)` | 背包裡有沒有、身上有沒有穿著 |
| `room:has_item(號碼)` | 地上有沒有 |
| `actor.name`、`actor.level`、`actor.guild`、`actor.race`、`actor:is_player()` | 名字、等級、公會（`"phys"`、`"spell"`）、種族（`"human"`……），只能看。生物的公會、種族是 `nil` |
| `random(1, 100)`、`hour()` | 擲骰子（包含兩頭）、遊戲裡現在幾點（0～23） |
| `actor:tell(文字)`、`room:echo(文字)`、`room:echo_except(actor, 文字)` | 只給他看、整個房間看、房間裡他以外的人看。文字可以用[顏色代碼](#顏色代碼) |
| `mob:command("say 歡迎")` | 生物照一般指令做，只能用生物本來能用的指令。`mob` 是生物（例如 `me`） |
| `mob:use(技能, actor)` | 生物對某人放一個技能，例如 `me:use("gift", actor)`。生物不用學、不用在打架。只能放增益技能（例如餽贈），對象是同一間房的玩家；放傷害技能算腳本出錯 |
| `actor:transfer(房號)` | 把他送到那間房。不能送進副本（副本只能用 enter 進去） |
| `room:load_item(號碼, 等級, 顏色)`、`actor:give_item(號碼, 等級, 顏色)` | 放一件物品在地上、給他一件。等級一定要寫；顏色不寫就沒有隨機屬性（跟重置的 `O`、`P` 一樣）。固定裝備放的當下檢查點數上限，超過算腳本出錯 |
| `actor:take_item(號碼)` | 從他的背包拿走一件 |
| `room:load_mob(號碼)` | 放一隻生物在這間房，跟重置的 `M` 一樣骰 `tier_roll`。不管 `M` 的 `limit`（作者自己用變數控制），但同一個區域檔、同號碼的生物最多 50 隻，超過算腳本出錯 |
| `room:door(方向, "open")` | 開、關、鎖、開鎖門（`"open"`、`"close"`、`"lock"`、`"unlock"`），兩邊一起變，不用鑰匙 |
| `mob:destroy()` | 讓生物消失（不留屍體） |
| `wait(秒數)` | 等幾秒再接著做（見下面） |

先不給：給經驗、給金幣、扣血、補血（影響平衡，要另外定）。

### 變數

| 寫法 | 記在哪 | 什麼時候清掉 |
|---|---|---|
| `local n = 1` | 這一次 | 跑完就忘 |
| `me.vars.名字`、`room.vars.名字` | 房間或生物身上 | 房間：區域檔重置時；生物：死掉時 |
| `actor.vars.名字` | 玩家身上，這個區域檔的；觸發的人是生物時，是那隻生物身上的 | 玩家：存進存檔，登出也在；生物：死掉時 |
| `actor:read_var("區域檔名", "名字")` | 玩家身上，別的區域檔的 | 只能看、不能改 |

- 值只能是 `nil`、`true`／`false`、數字、字串，不能存表格。名字可以用中文：`actor.vars["包子"]`。
- 存檔裡多一層區域檔名：`vars[區域檔名][名字]`，不同區域同名的變數分開。

### wait

- `wait(秒數)`：等的時候世界照跑。回來時伺服器先檢查：主人不在了（副本釋放、生物死掉或消失），
  或觸發的人不在了（離線、死掉、不在同一個房間），就默默停掉。沒有觸發的人的時機（`on_timer`、`on_born`、`on_reset`）只看主人。
- 一次最長 600 秒，超過就停掉腳本、記一筆錯誤。同一個主人同時在等的最多 10 個，超過的新觸發先不跑。
- `on_command` 跑到第一個 `wait` 就算擋住（指令要馬上決定）。`on_death` 裡 `wait` 回來時牠已經不在了，會停掉。
- 重開機時，正在等的腳本會不見，不會存起來。

### 上限、出錯

- 指令數上限：每一段（開始到第一個 `wait`、之後每兩個 `wait` 之間）10 萬個指令。
- 出錯（包括超過指令數、`wait` 超過 600 秒、上面那些「算腳本出錯」）：只停掉這一次，下次觸發照樣跑；玩家看不到；
  伺服器記一筆（哪個區域、哪個房間或生物、第幾行、錯在哪），線上的 imm 看到一行提醒。
- 沙箱：碰不到檔案、網路、作業系統，也沒有 `coroutine`。字串的方法只有 `byte`、`char`、`len`、`lower`、`upper`、`sub`、`format`、`rep`、`reverse`，
  算中文字數用 `utf8.len`（`#` 和 `sub` 是算 byte，一個中文字 3 個）。

### 例子

守衛擋路（生物的腳本）：

```lua
function on_command(actor, cmd, arg)
  if cmd == "north" and not actor:has_item(5) then
    actor:tell("守衛擋住了你：「沒有通行證不能過去。」")
    return true
  end
end
```

接任務（生物的腳本）：

```lua
function on_say(actor, text)
  if text == "任務" and not actor.vars.got_task then
    actor.vars.got_task = true
    me:command("say 去北邊幫我找一把鑰匙吧，" .. actor.name .. "。")
    wait(3)
    actor:tell("老闆對你眨了眨眼。")
  end
end
```

兩隻生物對話（生物說的話不會觸發 `on_say`，所以用 `tell` 叫對方；生物 `tell` 生物，玩家看不到）：

```lua
-- 老闆的腳本：玩家說「開店」
function on_say(actor, text)
  if text == "開店" then
    me:command("say 夥計，開門做生意了！")
    me:command("tell 夥計 開門")
  end
end
```

```lua
-- 夥計的腳本
function on_tell(actor, text)
  if text == "開門" then
    wait(1)
    me:command("say 是，老闆！")
  end
end
```

## 檢查區域檔

寫完或改完區域檔，可以先用檢查工具確認格式對不對，不用開伺服器：

```sh
uv run python -m mud.areacheck                     # 檢查 areas/ 裡全部的區域檔
uv run python -m mud.areacheck areas/test.json     # 只檢查一個檔案
```

- 工具會照這份手冊檢查**每一個欄位**，把所有問題一次列出來，每一行都寫出是哪個檔案、哪一間房間、哪個欄位。
- 欄位要剛好：少了欄位、或多了這份手冊沒有的欄位（例如已經拿掉的 `door_flags`），都算錯。
- 只檢查一個檔案時，通到別的區域的出口，會去同一個資料夾的其他檔案找那間房。
- 伺服器開機時也用同一套規則檢查，所以工具說沒問題的檔案，伺服器一定載入得了。
- `key` 指到的物品存不存在，目前還不會檢查。

輸出的樣子：

```
✗ areas/broken.json：2 個問題
  - broken.json：房間 1 的 sector 要寫 0～10 的整數，不能是 12
  - broken.json：房間 2 往 south 的出口指到不存在的房間 107
檢查了 1 個檔案，共 2 個問題
```

## 顏色代碼

在文字裡寫代碼，送給玩家時會換成顏色，色碼跟 C 版一樣。

| 代碼 | 顏色 | 代碼 | 顏色 |
|---|---|---|---|
| `{r` | 紅 | `{R` | 亮紅 |
| `{g` | 綠 | `{G` | 亮綠 |
| `{y` | 棕 | `{Y` | 黃 |
| `{b` | 藍 | `{B` | 亮藍 |
| `{m` | 紫 | `{M` | 亮紫 |
| `{c` | 青 | `{C` | 亮青 |
| `{w` | 灰 | `{W` | 白 |
| `{D` | 深灰 | `{x` | 回到原本的顏色 |

- 要印出 `{` 本身，就寫 `{{`。
- 換了顏色，記得在後面用 `{x` 換回來，不然後面的字都會是那個顏色。
- 顏色不能一層包一層：`{x` 一律回到原本的顏色，不會回到外層的顏色。

例如 `"description": "牆上有一行{R紅色{x的字。\n"`，「紅色」兩個字會變成亮紅色。

## 範例

完整的範例在 `areas/test.json`，裡面有兩間房間，南北相連：

- 房間 1「測試房間（南）」：北邊有出口，出口有木門（重置 `D` 讓它一開始開著），房間裡有一塊可以細看的牌子。
- 房間 2「測試房間（北）」：南邊有出口，出口也有木門（門兩邊都要寫），有腳本 `areas/test/鐘聲.lua`（每 60 秒一次鐘聲）。
- 生物 1「測試商人」有腳本 `areas/test/商人.lua`：有人說「你好」就回話。

副本和腳本的完整例子是 `areas/academy.json`（教學學院，`area_number` 200）：鎖著的門要去別的房間拿鑰匙、生物用腳本放餽贈、打倒稻草人用腳本開門、說「畢業」用腳本送回 101，規則見[玩家角色手冊](玩家角色手冊.md#教學學院)。
